# Alfa News backend

Шаблон FastAPI: Python 3.13, SQLAlchemy 2 (async), asyncpg, PostgreSQL 17,
Alembic и uv. Версии зависимостей зафиксированы в `uv.lock`.

## RSS-новости

При обычном запуске API из `app.main:app` автоматически запускается встроенный
RSS-воркер: четыре параллельные asyncio-задачи в том же процессе. Отдельная
команда, контейнер воркера или брокер не нужны. XML разбирается в потоках,
чтобы не блокировать обработку HTTP-запросов. Воркер останавливается до закрытия БД.

Первоначально подключены пять источников:

| Код | Источник | Интервал |
| --- | --- | --- |
| `rbc` | РБК: политика, экономика, компании | 90 секунд |
| `kommersant` | Коммерсантъ: деловая и политическая повестка | 120 секунд |
| `vedomosti` | Ведомости: экономика и бизнес | 120 секунд |
| `bfm` | Business FM: новости для бизнеса | 120 секунд |
| `klerk` | Клерк: налоги, бухгалтерия, предпринимательство | 300 секунд |

После обновления выполните `docker compose up --build -d --wait` из `backend`.
Сервис `migrate` применит миграцию `0004_rss_news`, затем запустится API.
Для локального запуска: `uv sync --locked`, `uv run alembic upgrade head`,
`uv run uvicorn app.main:app --reload`. Первый опрос выполняется автоматически;
загружается доступное окно RSS, а не полный архив издания.

### Чтение новостей

Требуется Bearer JWT из `/user/login`. Новостной корпус общий для всех
авторизованных пользователей, независимо от членства в компаниях.

| Метод | Назначение |
| --- | --- |
| `GET /news` | Новости, новые по времени обнаружения первыми |
| `GET /news/{news_id}` | Публикация с атрибуцией и ссылкой на оригинал |
| `GET /news/sources` | Источники, состояние лент и признаки проблем |

У `/news` есть `limit` (1–100, по умолчанию 20), `cursor`, `source`, `topic`,
`published_from`, `published_to`, `seen_from`, `seen_to`. Даты — ISO 8601 с
часовым поясом, границы включительные. Ответ: `items` и `next_cursor`;
передавайте полученный курсор со всеми прежними фильтрами для следующей страницы.
Курсор основан на `(first_seen_at, id)`, поэтому публикации с одинаковой датой
обнаружения не теряются между страницами. Новые записи, поступившие после первой
страницы, появятся при обновлении списка с начала.

Темы: `economy`, `politics`, `business`, `finance`, `taxes`, `regulation`,
`technology`, `other`. Исходные рубрики сохраняются отдельно; классификация
выполняется детерминированными правилами по рубрикам и настройкам источника.
Дата публикации, описание, авторы и изображение могут отсутствовать. Даты
сохраняются в UTC; время обнаружения не выдаётся за время публикации.
Для всех пяти лент текущего каталога сохраняется полный текст, если его прислал сам RSS.
Страницы статей при этом не скачиваются.

### Расширение каталога

Каталог — `app/services/rss/sources.json`. Одна запись описывает ленту;
несколько записей могут иметь один `code` издания и разные `feed_code`.
Новые обычные RSS/Atom-ленты подключаются без отдельного парсера. После изменения
каталога перезапустите приложение (в Docker — с пересборкой).

Обязательные поля: `code`, `name`, `site_url`, `feed_code`, `url`, `interval`,
`allowed_hosts`. Дополнительные: `enabled`, `kind`, `adapter` (`generic`/`rbc`),
`default_timezone`, `guid_scope` (`feed`/`source`), `default_topics`,
`category_mapping`, `store_content`. По умолчанию GUID имеет область одной ленты,
часовой пояс — `Europe/Moscow`. Для новых лент `store_content` по умолчанию выключен;
в пяти текущих записях каталога он включён явно.
`category_mapping` связывает исходную рубрику со списком наших тем.
Для отключения ленты задайте `enabled: false`; не удаляйте её историю из БД.
Смена URL сбрасывает старые HTTP-валидаторы и незавершённый снимок.

### Надёжность и диагностика

Ленты распределяются через PostgreSQL `FOR UPDATE SKIP LOCKED`, с арендой и
токеном владельца. Это работает и при нескольких процессах/репликах API.
Сеть не удерживает транзакцию БД; запись публикаций сериализована только в рамках
одного издания. GUID и нормализованные URL хранятся как уникальные ключи.
Публикация в нескольких лентах издания сохраняется один раз; материалы разных
изданий об одном событии остаются отдельными. Исчезновение записи из RSS не удаляет её.

Изменившиеся ответы сохраняются сжатыми в `rss_snapshots` до разбора.
Если процесс упал или транзакция откатилась, после истечения аренды следующий
воркер повторно обрабатывает сохранённый ответ без сетевого запроса. ETag и
Last-Modified подтверждаются только после успешной записи. Ошибочные записи
изолируются в `rss_item_errors`, результаты опросов — в `rss_runs`.
При ошибках запроса применяется backoff, при 429 учитывается `Retry-After`.
Доступ ограничен разрешёнными HTTPS-доменами и публичными IP, проверяется TLS,
запрещены XML DTD/внешние сущности; ограничивается распакованный размер ответа.

Настройки `.env` (также передаются через Compose):

| Переменная | По умолчанию |
| --- | --- |
| `RSS_ENABLED` | `true` |
| `RSS_CONCURRENCY` | `4` |
| `RSS_REQUEST_TIMEOUT_SECONDS` | `30` |
| `RSS_MAX_RESPONSE_BYTES` | `5242880` |
| `RSS_LEASE_SECONDS` | `120` |
| `RSS_SNAPSHOT_RETENTION_DAYS` | `7` |
| `RSS_RUN_RETENTION_DAYS` | `30` |

В одном процессе выполняется максимум один запрос к одному домену одновременно.
При нескольких процессах аренда защищает каждую ленту; отдельные ленты одного
домена в разных процессах могут опрашиваться параллельно. Для выбранных пяти
источников домены различаются.

`GET /news/sources` показывает последнее успешное обновление, появление новых
публикаций, число ошибок и `needs_attention`. Признак выставляется после трёх
ошибок подряд, значительного опоздания опроса или суток без новых публикаций.
Это диагностический сигнал, а не доказательство поломки: возможны выходные
или паузы публикаций. Технические ошибки и статистика пишутся в лог
`app.services.rss.worker` (для статистики успешных опросов включите уровень INFO).
Очистка снимков и журналов выполняется раз в час; незавершённые снимки защищены
от удаления. Сами новости автоматически не удаляются.

RSS содержит конечное окно: после долгого простоя исчезнувшие из ленты записи
нельзя гарантированно восстановить. Смысловое объединение новостей в сюжеты,
персонализация по компаниям и загрузка HTML-статей в эту версию не входят.

### Проверки RSS

`uv run pytest tests/test_rss.py` выполняет проверки без внешних запросов.
Интеграционные тесты в `tests/test_rss_integration.py` запускаются при заданной
`RSS_TEST_POSTGRES_DB`: укажите отдельную БД с применёнными миграциями и обычными
`POSTGRES_*` настройками. Они проверяют конкурентный захват, откат транзакций,
восстановление снимков, дедупликацию, API и отзывчивость API при работе воркера.
В обычных тестах автоматический опрос живых RSS отключён через `tests/conftest.py`.

## Запуск в Docker

Из папки `backend` (PowerShell):

```powershell
Copy-Item .env.example .env
# Сгенерируйте секрет и сохраните его в JWT_SECRET в .env:
python -c "import secrets; print(secrets.token_hex(48))"
docker compose up --build -d --wait
```

Compose дожидается готовности PostgreSQL, выполняет миграции отдельным сервисом
`migrate`, затем запускает API. Данные БД сохраняются в именованном томе.
Пароль из примера предназначен для локальной разработки. При первом запуске
можно изменить его в `.env`; для существующего тома изменение переменной
не меняет пароль пользователя PostgreSQL.

- Swagger UI: http://localhost:8000/docs
- Корневой адрес `/` перенаправляет в Swagger. JS, CSS и иконка Swagger UI
  поставляются с приложением: браузеру не нужен доступ к внешним CDN.
- OpenAPI: http://localhost:8000/openapi.json. В Swagger доступны поиск по
  методам, отправка запросов и время ответа, описаны успешные ответы и ошибка 503.
- Проверка процесса: `GET http://localhost:8000/health` → `{"status":"ok"}`.
- Готовность с запросом `SELECT 1`: `GET http://localhost:8000/health/ready`
  → `{"status":"ok","database":"ok"}`; при недоступной БД — HTTP 503.

Порты по умолчанию доступны только на локальной машине.
Настройки портов: `API_PORT` и `POSTGRES_PORT` в `.env`.
В контейнерах БД доступна по имени `db`, на хосте — по `localhost`.

```powershell
docker compose logs -f api migrate
docker compose down
```

`docker compose down` сохраняет данные; добавление `--volumes` удаляет их.

## Локальная разработка

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/).
Из папки `backend`:

```powershell
Copy-Item .env.example .env
# Задайте JWT_SECRET в .env (случайный секрет минимум 32 символа).
uv sync --locked
docker compose up -d db --wait
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

Если `.env` уже существует, сохраните свои настройки вместо повторного копирования.
Для разработки без Docker достаточно доступного PostgreSQL: задайте его
параметры `POSTGRES_*` в `.env`.

## Структура

```text
app/
  main.py          # Фабрика приложения и lifespan
  api/            # Healthcheck, пользователи, Bearer JWT dependency
  core/config.py   # Настройки из окружения и .env
  db/base.py       # Базовый класс ORM-моделей
  db/session.py    # Engine, пул и dependency SessionDep
  models/user.py  # Таблица users
  schemas/user.py # Тела запросов и ответов
alembic/           # Конфигурация и версии миграций
tests/             # Проверки healthcheck
```

В обработчиках используйте `SessionDep` для получения `AsyncSession`.
Изменения сохраняйте явным `await session.commit()` либо через
`async with session.begin()`. Закрытие сессии освобождает соединение и
откатывает незавершённую транзакцию. При остановке приложения пул закрывается.

## Миграции

Миграция `0001_create_users` создаёт `users`: `user_id UUID PRIMARY KEY DEFAULT
gen_random_uuid()`, уникальный `email`, `password_hash`, необязательный `full_name`
и `auth_version` для отзыва токенов после смены пароля.
Новые модели создавайте на основе `app.db.base.Base`
и импортируйте их модули в `alembic/env.py` перед `target_metadata`.
Проверьте сгенерированную миграцию перед применением:

```powershell
uv run alembic revision --autogenerate -m "create initial tables"
uv run alembic upgrade head
```

После добавления миграций перезапустите Compose с пересборкой, чтобы
сервис `migrate` применил их из нового образа.

## Авторизация

JWT подписан HS256, действует 24 часа, refresh-токенов нет.
`JWT_SECRET` хранится в `.env` (не в Git); `JWT_EXPIRE_MINUTES=1440` задаёт срок.
Без секрета выдача и проверка JWT возвращают 503.
Email используется как `login`, приводится к нижнему регистру.
Пароли длиной 8–128 символов хранятся только в виде Argon2id-хэша.
UUID создаётся PostgreSQL при вставке пользователя.

| Метод | Путь | JSON / доступ | Ответ |
| --- | --- | --- | --- |
| POST | `/user/register` | `login`, `password`, необязательный `fullName` | 201: `userId`, `login`, `fullName` |
| POST | `/user/login` | `login`, `password` | 200: `access_token`, `token_type`, `expires_in` |
| POST | `/user/reset-password` | `userId`, `oldPassword`, `newPassword`; Bearer JWT с `sub = userId` | 204 |
| GET | `/user/{userId}` | Bearer JWT с `sub = userId` | 200: `userId`, `login`, `fullName` |

В Swagger выполните регистрацию, затем вход. Скопируйте `access_token` в
**Authorize** (без префикса `Bearer`). После смены пароля все ранее выданные
токены этого пользователя перестают работать; войдите с новым паролем.
Хэши паролей в ответах не возвращаются. Повторный email — 409,
неверные учётные данные или JWT — 401, доступ к чужому userId — 403.

Интеграционные тесты запускаются при заданной `AUTH_TEST_POSTGRES_DB`:
укажите отдельную тестовую БД с применёнными миграциями (тесты создают пользователей).
Без этой переменной они пропускаются; остальные тесты не требуют PostgreSQL.

## Загрузка CSV бизнес-контекста

Три метода доступны в Swagger в разделе **CSV imports** после входа и Authorize.
Запросы используют `multipart/form-data`, имя поля файла — `file`.
Отдельных ролей для импорта нет; требуется Bearer JWT. Доступ к строкам CSV
проверяется по членству пользователя в компаниях.

| Метод | Назначение | Обязательные колонки |
| --- | --- | --- |
| `POST /imports/companies` | Юридические лица | Все 24 поля из описания ниже |
| `POST /imports/persons` | Обезличенные физлица и связи с компаниями | `SYNTHETIC_F`, `SYNTHETIC_U`, `CITY_NAME`, `RC_NAME` |
| `POST /imports/payments` | Направленные платёжные связи | `PAYER`, `BENEFICIARY`, `PAY_AMT`, `PAY_CNT` |

Колонки компаний: `SYNTHETIC_U`, `GROUP_ID`, `ORG_TYPE`, `OKFS_NAME`,
`COMPANY_AGE_YEARS_GRADATION`, `ECO_MARK_LABEL`, `MAINOKVED_CODE`, `MAINOKVED_NAME`,
`NEGATIVEMARK`, `AMOUNT_WORKERS_FNS_GRADATION`, `AMOUNT_WORKERS_SPARK_GRADATION`,
`CL_TYPE`, `CL_PRODUCT_RKO_MARK`, `CL_PRODUCT_GAR_MARK`, `CL_PRODUCT_LOA_MARK`,
`CL_PRODUCT_LEA_MARK`, `CL_PRODUCT_DEP_MARK`, `CL_PRODUCT_ZPP_MARK`, `FTS_FLAG`,
`FTS_COUNTRY_NAME`, `FACTORING_MARK`, `REVENUE_COMPANY`, `CITY`, `REGION`.
Порядок колонок произвольный. Дополнительные колонки компаний сохраняются
в `source_data`. Имена исходных файлов не проверяются: тип выбирается ручкой,
а формат — заголовком CSV.

Пример PowerShell (переменная `$token` содержит JWT, полученный через `/user/login`):

```powershell
curl.exe -X POST "http://localhost:8000/imports/companies" -H "Authorization: Bearer $token" -F "file=@df_Uid_data_hack.csv"
curl.exe -X POST "http://localhost:8000/imports/persons" -H "Authorization: Bearer $token" -F "file=@persons.csv"
curl.exe -X POST "http://localhost:8000/imports/payments?encoding=cp1251" -H "Authorization: Bearer $token" -F "file=@payments.csv"
```

Формат:

- UTF-8 с/без BOM по умолчанию; Windows-1251 через `?encoding=cp1251`.
- Разделитель `,`, `;` или tab определяется по заголовку. Можно задать явно:
  `?delimiter=%3B` для `;` или `?delimiter=%09` для tab.
- ID и ОКВЭД сохраняются текстом, включая ведущие нули.
- Флаги: `0/1`, `0.0/1.0`, `false/true`, `no/yes`, `нет/да`.
  Неизвестные значения атрибутов: пустая ячейка, `null`, `none`, `nan`, `na`, `n/a`.
  Идентификаторы обязательны и не преобразуются через этот список.
- Выручка необязательна. `PAY_AMT` и `PAY_CNT` обязательны и неотрицательны;
  количество — целое 64-битное число. Суммы сохраняются как `numeric`, не `float`.
  Десятичная запятая допустима при корректном CSV-экранировании или разделителе `;`.
- Категории возраста и численности остаются строками.
- При повторе `SYNTHETIC_U` сохраняется только последняя строка компании целиком,
  включая пустые значения. Предыдущие строки с этим ID не добавляются.
  Число пропущенных строк возвращается в `counts.skipped_duplicate_rows`,
  пояснение — в `warnings`. Для физлиц разные город/регион одного ID внутри
  файла по-прежнему считаются ошибкой.
- Лимиты: 100 MiB (104 857 600 байт) и 100 000 строк данных. Настройки `CSV_IMPORT_MAX_BYTES`
  и `CSV_IMPORT_MAX_ROWS` передаются в Compose; после изменения перезапустите API.

Если при загрузке возникает HTML-ошибка `413 Request Entity Too Large`, проверьте
внешний прокси: API уже принимает файлы до 100 МиБ, включая файлы размером 50 МиБ.
Для Nginx добавьте `client_max_body_size 101m;` в `server {}` API
(готовый фрагмент: `deploy/nginx/uploads.conf`) и выполните
`sudo nginx -t && sudo systemctl reload nginx` на сервере. Если внутри `location {}`
задан меньший лимит, его тоже нужно увеличить. Лимит запроса больше лимита файла,
поскольку multipart-запрос содержит заголовки и границы частей.

Ответ HTTP 200:

```json
{
  "import_id": "22871c6e-f4f0-48ad-b072-0d69b07e1761",
  "kind": "persons",
  "filename": "persons.csv",
  "row_count": 2,
  "encoding": "utf-8-sig",
  "delimiter": ",",
  "reused": false,
  "counts": {
    "companies": 0,
    "persons": 1,
    "links": 2,
    "payments": 0,
    "placeholder_companies": 0,
    "skipped_duplicate_rows": 0
  },
  "warnings": []
}
```

`counts` показывает число уникальных компаний, физлиц и связей, обработанных
в данном файле, а для платежей — число строк; это не счётчик только новых записей.
`placeholder_companies` — число созданных компаний с одним ID.
`row_count` включает все строки CSV, в том числе пропущенные повторы компаний.
Например, для 12 строк одного ID сохраняется одна компания, а
`counts.skipped_duplicate_rows=11`. Ответ содержит предупреждение о том, что
сохранена последняя строка; при повторном импорте файла предупреждение сохраняется.

Сначала создайте свою компанию через `POST /companies` либо импортируйте CSV
компаний. Новые компании из CSV автоматически привязываются к загрузившему
пользователю; существующие можно обновлять только их участникам. ID уже
существующей компании, включая заглушку, нельзя присвоить себе загрузкой CSV.

В CSV физлиц все `SYNTHETIC_U` должны относиться к доступным компаниям.
В каждой строке платежей минимум одна сторона должна быть доступной компанией.
Неизвестный контрагент создаётся с `is_placeholder=true`, но членство в нём
не предоставляется. Сам факт платежа или общей связи с физлицом не открывает
карточку контрагента. Компании и физлица обновляются по исходным ID, связи —
по паре ID. Отсутствующие в новом файле записи не удаляются.

Если физлицо связано также с недоступной компанией, менять его общие атрибуты
через импорт нельзя. Добавление связи с доступной компанией с неизменными
атрибутами физлица допустимо. При нарушении доступа весь файл отклоняется с 403,
без частичных записей.

В таблице `csv_imports` хранится журнал успешных импортов и `imported_by_user_id`.
Тот же набор байтов
в ту же ручку возвращает прежний `import_id` с `reused=true`, включая запросы
с другим именем файла. Он не выполняется заново даже после более нового импорта.
Проверка членства выполняется до возврата ранее сохранённого результата.
Одновременные импорты сериализованы транзакционной блокировкой PostgreSQL;
при превышении тайм-аута возможен 503, запрос можно повторить.

**Платежи:** строки сохраняются в `company_payments` с `import_id` и исходным
номером строки. Получатель и отправитель ссылаются на `companies`. Одинаковая
пара компаний может иметь несколько строк. Разные файлы считаются отдельными
наборами: они не суммируются и не заменяют друг друга автоматически. Поскольку
период и валюта в описании CSV не заданы, при анализе выбирайте нужный `import_id`,
чтобы не складывать перекрывающиеся снимки данных.

При ошибках формата возвращается 422 с `detail.code=invalid_csv` и списком
ошибок (до 20) с номерами строк и причинами. Файл сначала полностью проверяется,
затем сохраняется одной транзакцией. Если валидация или запись не удалась,
частично импортированных данных и записи успешного импорта не остаётся.
Превышение размера — 413; ошибка БД/тайм-аут — 503 без внутренних деталей.

Таблицы создаёт миграция `0002_create_company_imports`:
`csv_imports`, `companies`, `persons`, `company_person_links`, `company_payments`.
AI-summary и эмбеддинги на этом этапе не формируются.

Для обновления запущенного приложения:

```powershell
docker compose up --build -d --wait
```

Для интеграционных проверок установите `CSV_TEST_POSTGRES_DB` в имя отдельной
тестовой базы с применёнными миграциями. Проверяются реальные связи и суммы,
повторные и одновременные запросы, изоляция доступа и откат
транзакции при ошибке записи. Без переменной эти проверки пропускаются.

## Получение данных компаний

Методы доступны в Swagger в разделе **Companies**. Требуется Bearer JWT из
`/user/login` и членство в компании. Список содержит только доступные компании,
включая корректный `total` и фильтры. Чужой и несуществующий ID возвращают
одинаковый 404, включая дочерние ручки. Пользователи и компании связаны
многие-ко-многим через `company_memberships`; ролей внутри компании нет.

| Метод | Результат | Фильтры |
| --- | --- | --- |
| `GET /companies` | Краткие карточки компаний | `q`, `group_id`, `region`, `is_placeholder`, `limit`, `offset` |
| `GET /companies/{company_id}` | Все нормализованные поля, исходная строка CSV, ID последнего импорта и время обновления | — |
| `GET /companies/{company_id}/persons` | Обезличенные физлица, город/регион, ID импортов атрибутов и связи | `limit`, `offset` |
| `GET /companies/{company_id}/payments` | Строки платёжных агрегатов с отправителем, получателем, суммой, количеством, ID импорта и номером строки | `direction`, `import_id`, `limit`, `offset` |
| `GET /companies/{company_id}/payment-imports` | Файлы-импорты платежей с участием компании, время загрузки и число строк | `limit`, `offset` |

`company_id` — исходный `SYNTHETIC_U` либо ID, заданный/сгенерированный при создании.
Неизвестная или недоступная компания возвращает 404. Доступная компания-заглушка
возвращает 200, `is_placeholder=true`,
неизвестные атрибуты — `null`. Для известной компании без связей списки пусты.
Карточка не содержит AI-summary: это чтение загруженных исходных данных.

У всех списков `limit=20` (от 1 до 100), `offset=0` (неотрицательный).
Ответ: `{"items": [...], "total": 42, "limit": 20, "offset": 0}`;
`total` учитывает фильтры и не зависит от размера страницы.
Компании сортируются по текстовому ID, физлица — по ID, платежи — по ID записи,
импорты — по времени создания и UUID по убыванию. Это пагинация limit/offset,
при изменении данных между запросами состав страниц может меняться.

`q` ищет подстроку в ID, названии компании, названии ОКВЭД и городе без учёта регистра.
Символы `%` и `_` считаются буквальными. `group_id` и `region` — точные
совпадения. Фильтры списка компаний объединяются через AND.

Направления платежей относительно выбранной компании:

- `direction=all` (по умолчанию): компания — отправитель или получатель;
- `direction=incoming`: компания — получатель;
- `direction=outgoing`: компания — отправитель.

Самоплатёж присутствует в каждом подходящем направлении, но при `all` — один раз.
**Без `import_id` возвращаются строки всех импортов без суммирования.**
Разные файлы могут перекрываться. Для аналитики сначала получите
`payment-imports`, выберите набор и передайте его `import_id`. Неизвестный
`import_id` или импорт без платежей этой компании даёт пустой список.
`payment-imports.row_count` — размер всего файла,
`company_payment_rows` — число строк с участием выбранной компании.
Время импорта не является датой платежей; период и валюта из данных не выводятся.

Выручка и суммы в JSON передаются **строками** без потери десятичной точности
и без экспоненциальной записи: `"1.2E+5"` выдаётся как `"120000"`,
`"1E-7"` — как `"0.0000001"`. Счётчики остаются числами.
Ошибка БД — 503 без внутренних деталей; неверные фильтры и параметры — 422.

Примеры PowerShell:

```powershell
curl.exe "http://localhost:8000/companies?limit=20&is_placeholder=false" -H "Authorization: Bearer $token"
curl.exe "http://localhost:8000/companies/001" -H "Authorization: Bearer $token"
curl.exe "http://localhost:8000/companies/001/persons" -H "Authorization: Bearer $token"
curl.exe "http://localhost:8000/companies/001/payment-imports" -H "Authorization: Bearer $token"
curl.exe "http://localhost:8000/companies/001/payments?direction=incoming&import_id=$importId" -H "Authorization: Bearer $token"
```

`001` замените на реальный `SYNTHETIC_U`, `$importId` — на выбранный ID импорта.
OpenAPI содержит модели успешных ответов, описания полей и фильтров, примеры
значений, схему Bearer JWT и документированные ошибки. Для развёртывания
обновления используйте `docker compose up --build -d --wait`.

## Создание компаний и управление участниками

| Метод | Действие | Ответ |
| --- | --- | --- |
| `POST /companies` | Создать компанию и включить текущего пользователя | 201: полная карточка |
| `POST /companies/{company_id}/users` | Добавить зарегистрированного пользователя по `user_id` | 200: связь пользователя с компанией |
| `GET /companies/{company_id}/users` | Получить участников | Страница: UUID, полное имя, дата вступления |

Создание компании:

```json
{
  "id": "001",
  "name": "ООО Пример",
  "okved_code": "31.01",
  "okved_name": "Производство мебели",
  "city": "Казань",
  "has_credit": true
}
```

Обязательно только непустое `name`. Если `id` не передан, генерируется UUID
в текстовом виде. Если планируется загрузка CSV, задайте ID, совпадающий с
`SYNTHETIC_U`. Остальные нормализованные поля компании необязательны.
`name` сохраняется отдельно: в исходной схеме CSV названия компании нет.
Известные из CSV атрибуты при последующем импорте обновляются, заданное имя сохраняется.
Создание компании и членство автора сохраняются одной транзакцией.
Существующий ID — 409, без присвоения доступа и изменения компании.

Добавление участника:

```json
{
  "user_id": "22871c6e-f4f0-48ad-b072-0d69b07e1761"
}
```

Используйте реальный `userId` из регистрации пользователя. Добавлять участников
может любой текущий участник компании. Повторное добавление возвращает ту же
связь без изменения даты и автора добавления. Добавление в чужую компанию — 404;
неизвестный пользователь — 404 только после проверки доступа к компании.
Список участников не раскрывает email, пароли или токены.

Миграция `0003_company_memberships` создаёт связь с составным ключом
`(company_id, user_id)`, индекс по пользователю, время и автора добавления;
добавляет `companies.name` и автора CSV-импорта. **Ранее загруженные компании
не привязываются автоматически и остаются недоступными через пользовательские API.**
Прототип проверяет членство в приложении, а не владение реальным юридическим лицом.

## AI-сервисы (`app/services/llm/`)

Подпакет чистых функций для LLM-обработки: без БД, без HTTP-эндпоинтов, без парсеров.
Функции синхронные; бекенд вызывает их напрямую (в FastAPI — через `def`-эндпоинты
или `asyncio.to_thread`). Демо-режим без LLM API включается только явно
(`AI_LLM_MOCK=true`) — детерминированный mock-провайдер; если `AI_LLM_API_BASE` не задан
и mock не включён, вызовы падают с `LLMConfigError`, а не пишут демо-данные.

```text
app/services/llm/
  config.py            # настройки из .env с префиксом AI_
  schemas.py           # pydantic-схемы: NewsAnalysis, CompanyProfile, InsightDraft, ...
  provider.py          # LLM adapter: OpenAI-совместимый HTTP, JSON-валидация, ретраи
  embeddings.py        # BGE-M3 через Ollama: батчи, нормализация, cosine
  news_analysis.py     # готовая новость -> суммари + разметка + вектор
  company_profile.py   # поля компании -> профильный текст + векторы аспектов
  matching.py          # релевантность пары (компания, новость): косинус + правила
  insight.py           # Analyst -> Verifier -> (REVISE) и ответы на вопросы
```

### Контракты функций

| Функция | Вход | Выход |
| --- | --- | --- |
| `process_news_text(text, url=None)` | текст новости | `ProcessedNews`: `summary`, `markup` (topics, affected_sectors, regions, impact_kinds, facts, size_relevance), `vector` (1024d), `embedding_model_version` |
| `build_company_profile(fields, counterparties=None)` | `CompanyFields` (есть `from_csv_row` для строки CSV), список `Counterparty` | `CompanyProfile`: `main_text`, аспекты `industry/finance/ved` + их векторы |
| `score_relevance(profile, fields, news)` | профиль, поля, обработанная новость | `RelevanceScore`: `score` 0..1, `is_relevant`, `reasons[]`, `rules[]` |
| `build_insight(context, news, bank_passages)` | контекст компании, событие, чанки аналитики банка | `InsightResult`: черновик (facts, bank_position, interpretation, risks, opportunities, actions, claims с evidence_refs), вердикт APPROVED/REVISE/INSUFFICIENT, шаги для трейса |
| `answer_question(context, news, draft, question)` | инсайт + вопрос пользователя | текст ответа + шаг для трейса |

```python
from app.services import build_insight, build_company_profile, process_news_text, score_relevance
from app.services.llm.schemas import BankPassage, CompanyFields, CompanyContext, NewsEvent

processed = process_news_text(news_text, url=news_url)
profile = build_company_profile(CompanyFields.from_csv_row(csv_row), counterparties)
score = score_relevance(profile, fields, processed)

result = build_insight(
    CompanyContext(company_id="U_87", profile_text=profile.text.main_text),
    NewsEvent(text=processed.text, summary=processed.summary, url=processed.url),
    bank_passages=[
        BankPassage(document_id="rate_report_14092026", chunk_id="3", title="...", text="...")
    ],
)
# result.verification.status == "APPROVED" | "REVISE" | "INSUFFICIENT"
```

Поиск по загруженной аналитике доступен через `/analytics/search` и функцию
`app.services.analytics.search.search_analytics`. Подключение найденных источников
к `build_insight` выполняется вызывающим кодом. Не следует превращать произвольный
загруженный PDF в `BankPassage` без проверки издателя: этот тип означает позицию банка.

| Переменная | Назначение |

Учёт токенов: `USAGE_LEDGER.report()` возвращает вызовы и токены по purpose —
источник для `/metrics` и контроля дневного бюджета.

### Шлюз: эмбеддинги, реранкер и короткая оценка новостей

**Эмбеддинги.** `EmbeddingsClient` сначала вызывает `POST {AI_LLM_API_BASE}/embeddings`; если шлюз
не ответил, вернул ошибку или вектор неверной размерности, запрос идёт в локальный Ollama (bge-m3).
После сбоя шлюз не опрашивается `AI_EMBED_GATEWAY_COOLDOWN_SECONDS` (60 с), чтобы не тормозить
каждый вызов. Версия векторов в БД не зависит от источника (`bge-m3:1024d`), поэтому модель шлюза
должна быть тем же bge-m3 — иначе векторы шлюза и Ollama будут несравнимы.

**Реранкер.** Если задан `AI_RERANK_MODEL`, лента компании отправляет в `POST {AI_LLM_API_BASE}/rerank`
профиль компании и сводки `AI_RERANK_TOP_K` лучших кандидатов. Оценка реранкера (0..1) заменяет
косинусную часть формулы, веса правил остаются. Оценки кэшируются в памяти
(`AI_RERANK_CACHE_SECONDS`). При недоступности реранкера оценка прежняя: «косинус + веса правил».

**Короткая оценка в ленте.** `GET /companies/{id}/news` для каждой новости отдаёт
`brief_impact` (персонализированная сводка), `risks`, `opportunities` (по 1–2 предложения,
риски и возможности — один элемент списка) и `bank_analytics` +
`bank_sources` (позиция аналитиков банка по PDF, выбранным через `PUT /analytics/bank-documents`;
`null`, если подходящих материалов нет). Оценка делается **одним** вызовом LLM и готовится фоном:

1. запрос ленты ставит новости страницы без актуальной оценки в очередь `news_assessments`
   (`assessment_status: "pending"`), сам LLM не вызывает;
2. `AssessmentWorker` ищет фрагменты аналитики банка, делает один вызов LLM и сохраняет результат;
3. следующий запрос ленты возвращает `assessment_status: "ready"`.

Оценка пересчитывается при изменении профиля компании, текста новости, модели, набора документов
банка или истечении `AI_ASSESSMENT_CACHE_HOURS`. Позиция банка сохраняется, только если модель
сослалась на реально найденный фрагмент. Подробная проверяемая интерпретация (Analyst → Verifier)
остаётся в `POST /companies/{id}/news/{news_id}/interpretation`; пока короткой оценки нет, лента
показывает данные готовой полной интерпретации.

### Векторный слой новостей (`models/repositories`)

Таблица `news_embeddings` (миграции `0005` и `0008`, pgvector — модель
`app/models/news_embeddings.py`): `article_id` → `news_articles.id` (FK CASCADE),
`summary`, `vector vector(1024)`, `analysis` (разметка из LLM), `embedding_model_version`,
fingerprint входа, статус/retry и lease; HNSW-индекс по cosine. `NewsAIWorker` запускается
в lifespan API рядом с RSS worker, забирает ограниченные порции и не держит транзакцию БД
во время LLM/Ollama. HTTP-сводка читает только готовые актуальные строки и никогда не
запускает AI. При отсутствии LLM-конфигурации worker ждёт, а API и RSS продолжают работу.

Вся работа — в `app/repositories/news_embeddings.py` (async, `AsyncSession`):

| Функция | Вход | Выход |
| --- | --- | --- |
| `process_and_store_news(session, ids)` | айди новостей из `news_articles` | `ProcessOutcome`: пишет результат и пропускает только точный fingerprint (source text/content hash, prompt, LLM provider/model, embedding model) |
| `load_ready_news_embeddings(session, articles, settings)` | статьи и активная конфигурация | актуальные `ready` строки; только БД, без network |
| `fetch_news_records` / `fetch_news_events` | айди новостей | только готовые актуальные AI-данные; event сохраняет `published_at` |
| `fetch_news_event(session, article)` | статья | AI event либо явно помеченный RSS fallback + warning + текущий fingerprint |
| `rank_relevant_for_company(session, profile, fields)` | готовый профиль компании; опц. `article_ids`, `min_score`, `limit`, `since`, `candidates` (топ-N ближайших по pgvector, по умолчанию 500; `None` — без отбора), `settings` | `[RelevanceScore]` отсортировано по `score` desc, `is_relevant` по порогу 0.35 |

Пример:

```python
outcome = await process_and_store_news(session, article_ids, llm=llm)
scores  = await rank_relevant_for_company(session, profile, fields, min_score=0.35)
events  = await fetch_news_events(session, [scores[0].news_id])
result  = build_insight(company_context, events[0], bank_passages=[])
```

При обновлении существующего Compose-инстанса сначала пересоздайте только контейнер БД
на образе `pgvector/pgvector:pg17`, сохранив volume, затем примените миграции:

```powershell
docker compose up -d --force-recreate db --wait
docker compose run --rm migrate
```

Не запускайте миграцию `0005_news_embeddings` на обычном `postgres:17`: расширение
`vector` должно быть установлено в образе сервера.

## Аналитические PDF

Базовый конвейер: PDF → текст/OCR → страницы и блоки с координатами → фрагменты
до 1800 символов → существующий `EmbeddingsClient` с BGE-M3 → поиск источников.
Он не вызывает LLM и не составляет сводку автоматически. Оригинал, страницы,
фрагменты, векторы и очередь хранятся в PostgreSQL. Примените миграцию
`0005_analytics_pdf` командой `alembic upgrade head` или пересоберите Compose.

### Swagger

После запуска API откройте `/docs`, авторизуйтесь JWT из `/user/login`, раздел **Analytics**.
Корпус общий для авторизованных пользователей, как RSS. Издатель указан загрузившим;
загрузка не удостоверяет подлинность материала и не публикует выводы от имени банка.

| Метод | Назначение |
| --- | --- |
| `POST /analytics/documents` | `multipart/form-data`: `file`, обязательный `publisher`, необязательные `title`, `published_at` (YYYY-MM-DD), `topics` через запятую |
| `GET /analytics/documents` | Каталог: `publisher`, `status`, `limit`, `offset` |
| `GET /analytics/documents/{id}` | Статус, количество страниц и фрагментов, предупреждения и ошибки |
| `PATCH /analytics/documents/{id}` | Уточнение названия, издателя, даты и списка тем после обработки |
| `GET /analytics/documents/{id}/passages` | Фрагменты, физические номера страниц и bbox; `limit`/`offset` |
| `GET /analytics/documents/{id}/pages/{number}` | Полный текст страницы, метод извлечения, блоки и координаты |
| `GET /analytics/documents/{id}/file` | Исходный PDF |
| `POST /analytics/documents/{id}/retry` | Повтор обработки; при наличии фрагментов повторяется только векторизация |
| `POST /analytics/search` | Текстовый, смысловой или гибридный поиск для будущих сводок и интерпретаций |

Загрузка возвращает **202** с `document.id`, `duplicate` и `status_url`.
Состояния: `queued → extracting → indexing → ready`. `parsed` означает, что текст
сохранён и полнотекстовый поиск работает, но векторизация отключена или BGE недоступен.
`failed` означает ошибку разбора PDF. Подробности — в `error`/`embedding_error`.
Повтор идентичного файла определяется по SHA-256 и возвращает существующий документ;
его метаданные не перезаписываются. Исправляйте их через PATCH. Изменение названия
обновляет поисковый текст и ставит в очередь повторную векторизацию.

Очередь использует `FOR UPDATE SKIP LOCKED`, аренду с продлением и токен владельца.
После падения процесса документ можно продолжить после истечения аренды (до 120 секунд).
OCR запускается в отдельном процессе с таймаутом, не блокируя API. Ограничения по
умолчанию: 50 МиБ (52 428 800 байт), 100 страниц, 900 секунд на разбор.
Размер PDF задаётся через `ANALYTICS_MAX_BYTES`, минимальный действующий лимит — 50 МиБ.
Меньшие значения (включая прежние `26214400` в серверном `.env`) автоматически
поднимаются до `52428800`; большие значения сохраняются. Для применения обновлённого
кода пересоберите и пересоздайте API: `docker compose up -d --build --force-recreate api`.
Ошибки одного PDF не останавливают очередь.

Пример тела `/analytics/search`:

```json
{
  "query": "Сохранение ключевой ставки и стоимость кредитования компаний",
  "mode": "hybrid",
  "limit": 8,
  "publisher": "Альфа-Банк",
  "as_of": "2026-10-23"
}
```

Также доступны `topic`, `document_ids`, `published_from`. `as_of` исключает отчёты,
опубликованные позже этой даты, и отчёты с неизвестной датой. Сам по себе фильтр
не определяет, какой прогноз был пересмотрен: автоматического связывания версий пока нет.
Дата извлекается из отдельной строки шапки/подвала первой страницы, а не из имени файла,
года copyright или дат внутри аналитического текста. Если точный день не указан,
дата остаётся `null`; её можно уточнить через PATCH.

Каждый результат содержит текст, издателя, дату, страницу, bbox, ссылку на PDF
и `evidence_ref` вида `analytics:<document_id>#<chunk_id>`. `score` — относительный
RRF-балл ранжирования, не вероятность достоверности. Встроенный русский полнотекстовый
поиск имеет GIN-индекс. Векторный поиск первой версии выполняет точное сравнение
с сохранёнными векторами (массивы PostgreSQL, без обязательного pgvector), поэтому
рассчитан на небольшой корпус. Сравниваются только векторы совместимой версии модели.
При недоступности BGE гибридный режим возвращает текстовый поиск с предупреждением;
чистый `semantic` возвращает 503. Вызывающий код должен отдельно определять достаточность
подтверждений: наличие результата поиска не доказывает применимость вывода к новости.

### OCR и локальный разбор папки

В Docker установлены языковые данные Tesseract `rus`/`eng`, путь настроен в образе.
При локальном запуске задайте `ANALYTICS_TESSDATA` — папку с `rus.traineddata` и
`eng.traineddata`, например из официального репозитория
[tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast).
Для Docker укажите `AI_EMBED_OLLAMA_HOST=http://host.docker.internal:11434`, если
Ollama работает на хосте; `127.0.0.1` внутри контейнера указывает на сам контейнер.

Из `backend`, без БД и без BGE:

```powershell
uv run python -m app.services.analytics ../analitics ../analitics/parsed --tessdata D:/path/to/tessdata --publisher "Альфа-Банк"
```

Команда создаёт JSON на каждый документ, `manifest.json` с результатами обработки
и `corpus.jsonl` с одной строкой на фрагмент. В JSONL сохранены SHA-256 исходника,
страница, bbox, текст, дата, издатель и стабильная ссылка `pdf:<sha256>#<chunk_id>`.
Этот офлайн-экспорт не загружает документы в БД API; для этого используйте ручку загрузки.
В предоставленной папке распознаны 9 PDF / 64 страницы / 117 фрагментов.

Числа, графики, таблицы и порядок чтения OCR требуют проверки по оригиналу.
Первая версия сохраняет текст и геометрию блоков, исключает страницы дисклеймеров
из поиска, но не превращает таблицы в проверенные финансовые показатели и не
извлекает причинные связи с помощью LLM. Все офлайн-фрагменты имеют `quality=unverified`.

Проверки: `uv run pytest tests/test_analytics.py`. Интеграционные проверки —
`tests/test_analytics_integration.py`; задайте `ANALYTICS_TEST_POSTGRES_DB` и
`POSTGRES_*` для **отдельной** БД с применёнными миграциями. Они проверяют полный цикл
загрузки/разбора/поиска, дубликаты, аренды, даты, повторную векторизацию и отказ BGE.

## Сводка компании и интерпретация новости

Маршруты находятся в разделах **Company news** и **Company news chat**. Нужен Bearer JWT и членство
в выбранной компании. Чужая или неизвестная компания возвращает одинаковый 404.

| Метод | Назначение |
| --- | --- |
| `GET /companies/{company_id}/news` | Быстрый список новостей без вызовов LLM или BGE |
| `POST /companies/{company_id}/news/{news_id}/interpretation` | Генерация при открытии новости или получение сохранённого результата |
| `POST /companies/{company_id}/news/{news_id}/chat/threads` | Создать личный чат по новости |
| `GET /companies/{company_id}/news/{news_id}/chat/threads/{thread_id}/messages` | Получить историю без запуска LLM |
| `POST /companies/{company_id}/news/{news_id}/chat/threads/{thread_id}/messages` | Задать вопрос по готовой подтверждённой интерпретации |

В сводке: `items`, `total`, `limit`, `offset`, `company_id`, `ranking_method`.
Карточка содержит заголовок, ссылку, источник, даты, `summary`, темы,
`relevance_score`, `relevance_reasons` и, если есть актуальный подтверждённый кеш,
краткие риски/возможности. `summary_origin=ai` означает сохранённое фоновое AI-суммари;
`summary_origin=rss` означает описание
из RSS, `title` — источник не дал описания и возвращён заголовок. Это не выдаётся
за AI-саммари. Правила учитывают описание деятельности, город/регион, банковские
продукты и общую деловую тематику; балл не является вероятностью влияния.
Риски и рекомендации не генерируются при открытии сводки.

Параметры GET: `limit` (1–100, default 20), `offset`, `source`, `topic`,
`published_from`, `published_to` (ISO 8601 с timezone, включительно),
`relevant_only` (default true). `relevant_only=false` также включает записи без
совпадений. Сортировка: балл, время обнаружения, UUID — по убыванию.
Полные исходные карточки по-прежнему доступны через `/news/{news_id}`.

Тела у POST нет. Первый запрос ожидает LLM, которая получает профиль компании
из нормализованных данных БД, доступный текст новости и выбранные фрагменты
аналитики. Денежные значения в контексте передаются точно, без float.
Отсутствующие данные не заменяются предположениями; при отсутствии полного
текста новости возвращается предупреждение об ограниченном контексте.
Вызовы модели выполняются в потоке, без удержания транзакции/соединения БД.

Ответ POST содержит `id`, `company_id`, `news_id`, `status`, `interpretation`,
`verification`, `steps`, `sources`, `warnings`, `model`, `is_demo`, `reused`,
`generated_at`. В `interpretation` — `headline`, `facts`, `bank_position`,
`ai_interpretation`, `risks`, `opportunities`, `suggested_actions`, `limitations`,
`claims`. Источники имеют `evidence_ref` и ссылку на новость или страницу PDF.

- `200`, `status=ready`: черновик одобрен проверяющим и прошёл проверку ссылок.
- `200`, `status=needs_revision` или `insufficient`: `interpretation=null`,
  причины доступны в `verification`; такой черновик не следует показывать как готовый.
- `202`, `status=generating`, `Retry-After: 2`: другая копия запроса уже работает.
  Повторите тот же POST через указанное число секунд; третий маршрут не нужен.
- `429`: заняты слоты модели; `502`: ошибка провайдера/формата ответа;
  `503`: LLM не настроена или БД недоступна; `504`: исчерпан общий срок генерации.
  После сбоя тот же POST допускает повторную попытку.

Для реального провайдера задайте `AI_LLM_API_BASE`, `AI_LLM_API_KEY` (если нужен),
`AI_LLM_MODEL`. При отсутствии адреса API возвращается 503: скрытого переключения
на демонстрационную модель нет. `AI_LLM_MOCK=true` включает явный деморежим с
`is_demo=true`; он не является реальной аналитикой.

Банковские фрагменты ищутся гибридным поиском; при недоступном BGE явно используется
текстовый fallback с предупреждением. Выберите документы через API (требуется JWT):

```http
PUT /analytics/bank-documents
Authorization: Bearer <token>
Content-Type: application/json

{"document_ids": ["00000000-0000-0000-0000-000000000001"]}
```

Замените UUID на реальные ID из `GET /analytics/documents`. Ручка заменяет весь набор,
удаляет повторы ID и возвращает сохранённый список. `GET /analytics/bank-documents`
показывает текущий набор. `{"document_ids": []}` отключает банковский контекст.
Неизвестный документ даёт 404; необработанный PDF, отсутствие фрагментов или даты — 409,
при этом прежний набор сохраняется. Выбор общий для всех пользователей, хранится в БД
и применяется без изменения env и перезапуска API, включая фоновые оценки и чат.
Изменение набора меняет ключ кеша; новые оценки запрашиваются при следующем открытии ленты.
Уже выполняющиеся запросы могут завершиться с прежним набором.
`AI_BANK_DOCUMENT_IDS` используется только пока выбор не был сохранён через API.
Для установки нужна миграция `0011_bank_analytics_selection` (`alembic upgrade head`).

Пригодны обработанные документы с известной датой
публикации не позднее дня запроса. Самостоятельно введённое поле `publisher`
не делает загрузку подтверждённой позицией банка. При пустом списке или отсутствии
совпадений передаётся пустой банковский контекст, что отражается в `warnings`.
Позиция банка без ссылки на выбранный источник не публикуется.

Миграции `0006_news_interpretations` и `0008_ai_background_state` хранят кеш,
фоновые состояния и личные чаты в PostgreSQL. Ключ зависит от
компании, версии новости, модели и промптов; результаты повторного поиска не меняют ключ.
Сохранённые банковские фрагменты проверяются по БД: другие фрагменты документа не сбрасывают кеш.
Повторное открытие возвращает `reused=true` без повторного поиска источников или вызова LLM.
Чат использует ту же сохранённую интерпретацию и её источники, включая результаты со старым ключом.
Изменение входных данных, использованных банковских фрагментов либо
истечение TTL запускает новый расчёт. Конкурентные запросы используют аренду
и токен владельца в БД; оборванную генерацию можно повторить после истечения аренды.

Настройки: `AI_INTERPRETATION_TIMEOUT_SECONDS=90` (общий срок),
`AI_INTERPRETATION_CONCURRENCY=2` (число активных генераций на процесс),
`AI_INTERPRETATION_CACHE_HOURS=24`. Compose передаёт настройки провайдера и кеша
в API. После изменения конфигурации перезапустите приложение; после обновления
кода примените `uv run alembic upgrade head` или пересоберите Compose.

Чат не создаёт интерпретацию автоматически: если актуального результата
`status=ready` нет, POST сообщения возвращает 409. `client_message_id` обязателен
и делает повтор безопасным. История принадлежит создавшему чат пользователю;
для старых страниц передавайте `before=next_before`. Ответ содержит проверенные
claims с типом `fact`, `bank_position` или `ai_inference` и только точные ссылки
на доступные источники. При отсутствии провайдера возвращается 503, скрытого mock нет.

Фоновая подготовка включается `AI_NEWS_WORKER_ENABLED=true`; интервал и размер пачки
задаются `AI_NEWS_WORKER_POLL_SECONDS` и `AI_NEWS_WORKER_BATCH_SIZE`.

Проверки: `tests/test_company_news.py`; интеграционные —
`tests/test_company_news_integration.py` при `COMPANY_NEWS_TEST_POSTGRES_DB` и
`POSTGRES_*`, указывающих на отдельную БД с миграциями. Проверяются доступы,
ранжирование без LLM, конкурентная генерация, кеш, сроки, источники и ошибки.

### Постепенное заполнение карточек на фронте

После быстрого `GET /companies/{company_id}/news` фронт может отправить видимые UUID
в `POST /companies/{company_id}/news/assessments/stream`:

```js
const response = await fetch(`/companies/${companyId}/news/assessments/stream`, {
  method: "POST",
  headers: {Authorization: `Bearer ${token}`, "Content-Type": "application/json"},
  body: JSON.stringify({news_ids: visibleNewsIds.slice(0, 20)}),
});
const reader = response.body.getReader();
const decoder = new TextDecoder();
for (;;) {
  const {value, done} = await reader.read();
  if (done) break;
  handleSseChunk(decoder.decode(value, {stream: true}));
}
```

Ответ имеет `Content-Type: text/event-stream`. События `assessment` содержат
`news_id` и статусы `queued`, `generating`, затем `ready`, `needs_revision`,
`insufficient` или `failed`. Только `ready` содержит `brief_impact`, `risks`,
`opportunities`, `bank_position` и подтверждённые банковские `sources`.
Завершение обозначается событием `done`; комментарий `: ping` поддерживает соединение.
Готовый кеш возвращается без повторного вызова LLM. Один запрос принимает до 20
уникальных UUID и использует обычный Bearer JWT и проверку членства в компании.

### Постепенная подробная интерпретация

`POST /companies/{company_id}/news/{news_id}/interpretation/stream` не требует тела
и возвращает `text/event-stream`. Вызов через `fetch` и чтение `response.body` такие же,
как в примере выше. События `progress` сообщают реальные стадии `preparing`,
`generating`, `verifying`, `revising`, `retrieving` или `waiting`. После работы аналитика
приходит `draft` с полным `draft`, номером `revision_version` и `verified=false`.
Новая редакция приходит полным snapshot и заменяет предыдущую на фронте.

Для реального провайдера каждая редакция начинается с `reset`
`{"revision_version":N,"verified":false}`. Следующие события `delta` содержат
`revision_version`, `field`, `text`, необязательный `index` элемента списка и
`verified=false`; фронт дописывает `text` только к указанному полю текущей редакции.
Потоком передаются только пользовательские поля разбора, а `claims` и служебные поля
появляются лишь в валидированном полном `draft`. При новом `reset` накопленный черновик
заменяется. Некоторые OpenAI-совместимые провайдеры не возвращают usage в streaming-ответе;
в таком случае счётчики токенов этого вызова помечаются как недоступные.

Событие `result` содержит обычный полный `InterpretationResponse`; только
`status=ready` публикует `interpretation`, а `needs_revision` и `insufficient` сохраняют
`interpretation=null`. Затем всегда приходит `done`. Ошибка передаётся событием `error`
с `detail`, необязательным `http_status` и `retryable`, после него также приходит `done`.
При non-ready результате или ошибке фронт должен удалить черновик либо пометить его
неуспешным и не показывать как подтверждённую интерпретацию.
Готовый кеш сразу даёт `result` с `reused=true` без `draft`; активная генерация даёт
стадию `waiting` и использует существующую DB-аренду, не запуская второй расчёт.
Комментарии `: ping` поддерживают соединение во время долгого вызова модели.

### Полный текст новостей

`content_text` — текст статьи, а `summary` — RSS-анонс. РБК отдаёт текст в
`rbc_news:full-text`; `content:encoded` у РБК содержит подпись фотографии и не используется.
В проверенных RSS Business FM, «Коммерсанта», «Ведомостей» и «Клерка» полного текста нет.
Отдельный `ArticleContentWorker` загружает страницы этих источников и извлекает тело статьи
из контейнеров издателя или JSON-LD `articleBody`. Меню, подписи и рекомендации исключаются.
Ограничения доступа и отсутствие тела статьи фиксируются как ошибка, а не как готовый текст.

В `GET /news` и `GET /news/{id}` добавлены `content_origin` (`rss` / `article`),
`content_status` (`pending` / `processing` / `retry` / `ready` / `unavailable`) и `content_error`.
Worker использует аренды PostgreSQL, ограничивает размер/время ответа, проверяет домены
редиректов и повторяет ошибки до пяти попыток. Обрабатываются и существующие новости.
Загрузка полного текста меняет `content_hash`: AI-кеши пересчитываются обычными workers.
Следующий опрос RSS сохраняет ранее загруженный текст; новая дата редакции запускает его обновление.

После обновления образа, перед запуском API:

```bash
alembic upgrade head
python -m app.services.rss.backfill
```

Вторая команда восстанавливает тексты из сохранённых RSS-снимков, включая старые записи
РБК с подписью фотографии вместо статьи. Снимки обрабатываются от новых к старым;
тексты из HTML и более новые редакции не перезаписываются. Остальное заполнит worker.
Настройки: `ARTICLE_CONTENT_ENABLED=true`, `ARTICLE_CONTENT_CONCURRENCY=2`,
`ARTICLE_CONTENT_POLL_SECONDS=2`. При закрытой подпиской статье или блокировке издателем
получение полного текста не гарантируется; причину показывает `content_error`.
